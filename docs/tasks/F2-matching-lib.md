- `draftFromMatch(stepsSource, result)` → a `VariantWrite['recipe']` whose ingredients are the matched ones (keeping base ids for base slots, with no ids for added ones) and whose steps, utensils and times come from `stepsSource`.

## Report

### Summary
- `frontend/src/lib/domain/matching.ts` implements `matchVariants`, `pin`, `clearUserPicks` and `draftFromMatch` with the fixed §5.2 signatures. All are pure; inputs are never mutated (tests freeze them).
- Ranking is exactly PROJECT §6.3 step 5: remembered-pick matches (user and auto picks) → favourite → preference score (sum of weights of the variant's `productSwaps`) → cook count → base first → older first (then matrix order).
- Custom mix: when no variant agrees with all user pins, the variant with the most pin matches wins, using the same tuple as tie-breaker. Picks that point at a slot or option that no longer exists are ignored.
- `shared/test-vectors/matching/F2.json` has 36 cases (generated by a throwaway script, not committed). 6 of them reuse the `variants/T00.json` matrices through `matrixFromCase`. `matching.test.ts` also runs invariants over every matrix in `variants/*.json`, so `B4.json` is covered automatically after a rebase. It also has a 50 variants × 40 slots benchmark (asserts < 150 ms).
- Coverage of `matching.ts`: 100 % lines.

### Deviations
- **Display position of added ingredients.** The task asks for added rows to follow the base row they come after, but the `VariantMatrix` carries no "after" data (API §5.1). Added slots are therefore listed after all base rows, in matrix (first-seen) order. See Requests.
- `RankedOption.compatible` means "supported by at least one compatible variant", taken literally from §6.3 step 7. In a custom mix there is no compatible variant, so every option is `compatible: false`. `supportCount` counts all variants supporting the option, not only the compatible ones.
- `draftFromMatch` keeps the ids of the `stepsSource` steps. It cannot tell base steps from steps added by a variant, because it has no base recipe. Base ingredient ids are detected through the `i:` keys of `result.picks`.
- The matching vector `expected` is a free-form object (the schema allows it). Keys used: `bestVariantId`, `isCustomMix`, `compatibleVariantIds`, `picks` (subset), `absentPickSlots`, `ingredientIds`, `optionOrder`, `optionCompatible`, `optionSupport`, `selected`. The schema was not tightened.
